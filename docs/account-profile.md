# お客様情報 (氏名・電話・住所)

2026-09-05実装。ORI付与を入口にしたリスト取りが目的で、取得した連絡先は今後の
アップセルに使う (運用判断)。

## なぜ「必須」でも使えるままにするのか

この機能の値打ちは、**入力しなかった人を区別できること**にある。入力を利用の
条件にすると、入力しない層はそもそもウォレットを使わないので、区別する対象が
消えてしまう。だから `REQUIRED` に設定しても:

- 残高照会も取引も、これまでどおり通る
- ホーム画面に入力をお願いする帯が出るだけ
- 「今回は入力しない」を選べる

「入力しない」は `account_profiles.declined_at` に記録する。**未入力のまま
放置している人と、明示的に断った人は別のセグメント**なので、区別できるように
しておく必要がある。断った人には帯を出し続けない (出し続けても入力されないし、
断ったという情報はもう取れている)。

## 管理画面から項目ごとに設定する

`/profile-config` (アカウント・取引 > お客様情報の入力設定)。

| 設定 | 意味 |
|---|---|
| **非表示** (`HIDDEN`) | 入力欄を出さない。送られてきても**400で拒否する** |
| **任意** (`OPTIONAL`) | 入力欄を出す。空欄でもよい |
| **必須** (`REQUIRED`) | 入力をお願いする表示が出る。ただし利用は妨げない |

加えて `promptEnabled` でホーム画面の帯そのものを止められる。項目の設定は
残るので、メニューからの入力は続けられる。

設定は `account_profile_config` の単一行 (`id = "default"`、
`CommonUserHubConfig` と同じ方式)。行が無ければ既定値
(氏名・電話・郵便番号・住所は任意、カナは非表示) を使う。

### HIDDENを「無視」ではなく「拒否」にする理由

黙って捨てると、利用者には保存できたように見える。設定を閉じた直後に古い画面を
開いたままの人が入力した場合、保存されたつもりで二度と戻ってこない。

### 設定変更をAPIから取る理由

画面はビルド時の値ではなく `GET /api/v1/accounts/me/profile` の `config` に
従って入力欄を出し分ける。管理画面で設定を変えても**再ビルドが要らない**ように
するため (`docs/login-methods.md` のログイン方法と同じ考え方)。

## 保存する値は正規化する

電話番号と郵便番号は数字だけに揃えてから保存する。`090-1234-5678` と
`０９０１２３４５６７８` が別々に貯まると、後で名寄せや配信リストに使うときに
突き合わせられないため。

| 項目 | 受け付ける形 | 保存する形 |
|---|---|---|
| 電話番号 | ハイフン・空白・全角可 | `0`始まりの数字10桁または11桁 |
| 郵便番号 | ハイフン・全角可 | 数字7桁 |
| 都道府県 | 47個のいずれか | そのまま |
| お名前 (カナ) | 全角カタカナと空白 | 前後の空白を落とす |

住所は都道府県・市区町村・町名番地が**揃って初めて**「入力済み」とみなす
(建物名は常に任意)。県だけ入っている状態を入力済みとすると、送り先として
使えないものを入力済みに数えてしまう。

## 個人情報としての扱い

`ove_accounts` に足さず `account_profiles` という専用テーブルに置いている。
ここに入るのは個人情報だけなので、**保管・削除・匿名化の対象範囲をこの
テーブル1つに閉じ込められる**。

退会後の匿名化 (`AccountAnonymizationService`) では、部分的に消すのではなく
**行ごと削除**する。氏名・電話・住所しか入っておらず、退会済みの相手に
セグメントを残しておく理由も無いため。

> 匿名化の仕組み自体は既定OFF (`ENABLE_ACCOUNT_ANONYMIZATION`) のままで、
> 有効化は法務判断待ち (`docs/account-anonymization.md`)。**この機能を本番で
> 使い始める前に、利用目的・保管期間・削除の扱いを利用規約とプライバシー
> ポリシーへ記載すること。**

## 管理画面での見え方

LINEログインで登録したアカウントは `display_name` が空のままになる
(LINEのIDトークンからは `lineUserId` と `email` しか取れない)。そのため
アカウント一覧では `ORI-ACC-...` しか手がかりが無かった。

アカウント詳細 (`/accounts/{id}`) に「お客様情報」の欄を追加し、未入力・
本人が断った・入力済みのどれなのかが分かるようにしている。

## エンドポイント

| メソッド | パス | 権限 |
|---|---|---|
| `GET` | `/api/v1/accounts/me/profile` | 利用者本人 |
| `PUT` | `/api/v1/accounts/me/profile` | 利用者本人 |
| `POST` | `/api/v1/accounts/me/profile/decline` | 利用者本人 |
| `GET` | `/api/v1/admin/profile-config` | `SUPER_ADMIN` / `INTEGRATION_ADMIN` / `AUDITOR` |
| `POST` | `/api/v1/admin/profile-config` | `SUPER_ADMIN` / `INTEGRATION_ADMIN` |

`PUT` は指定した項目だけを更新する (省略は現状維持、空文字は削除)。入力が
あった時点で `declined_at` は解除する。設定変更は監査ログ
(`ACCOUNT_PROFILE_CONFIG_UPDATED`) に前後の値を残す。
