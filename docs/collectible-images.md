# カード画像のウォレット側保管

NFTコレクションのカード画像を、外部マーケットのURLを参照するだけの状態から、
**ウォレット自身が保管して配信する**形へ変えた。

## なぜ持つのか

これまでは `collectible_assets.image_url` に外部のURLを保存し、そのまま表示していた。
この形だと、**マーケット側の配信が止まった時点で、利用者が買ったカードの絵柄が
見えなくなる。** 保有の記録はこちらにあるのに、見た目だけが他所に依存している状態
だった。

将来ブロックチェーンへ載せるまでの間、カードの実体は画像データそのものなので、
そこを他所任せにしない。

## いつ取り込むか

- `entitlement.granted` を受け取ったとき (マーケットからの付与)
- 管理画面でカードマスターを作成・更新したとき

いずれも**本来の処理が終わってから、トランザクションの外で**行う。外部への通信を
トランザクション内に入れると、相手が遅いだけでDBの接続を掴み続けることになるため。

### 取り込めなくてもカードは配る

**画像が無いことより、買ったカードを受け取れないことの方が害が大きい。** 取得に
失敗しても付与・保存は成立させ、失敗は `collectible_images` に記録して後から
取り直す (15分ごと、`JOB_COLLECTIBLE_IMAGE_INGEST`)。取り込めていない間は、
これまでどおり取得元のURLをそのまま表示する。

試行が `MAX_INGEST_ATTEMPTS` 回に達したものは自動再取得の対象から外す。届かない
URLへ永久に通信を繰り返さないため。外した分は管理画面から対象へ戻せる
(後述「取り込み状況を管理画面から見る」)。

### 保管先を設定する前に登録されたカードも拾う

`registerAndIngest()` は保管先が未設定のとき**登録ごと行わずに戻る**。取り込めない
ものを待ち行列へ積んでも、試行回数だけが減っていくためである。その結果、
「先にカードを登録し、後から R2 を設定した」場合、そのカードには
`collectible_images` の行が無い。定期実行の `retryPending()` は既にある行しか
見ないので、これだけでは**そのカードの画像が永久に取り込まれない**。

そのため定期実行はまず `backfillFromCatalog()` で、カードマスター
(`collectible_assets`) と保有 (`collectible_holdings`) に載っているのに取り込み
対象へ入っていないURLを拾い、登録してから取得へ進む。

保有側のスナップショット列 (`image_url_snapshot` / `thumbnail_url_snapshot`) も
対象にする。カードマスターを後から差し替えても、既に配布済みの保有は付与時のURLを
表示し続けるため、マスターだけを見ると実際に表示されているURLを取りこぼす。

## 取得元URLを単位にしている

保有 (`collectible_holdings`) ごとではなく**取得元URL**ごとに1件持つ。同じURLは
同じ画像なので、カードの種類や保有者をまたいで1件で足りる。

付与時のスナップショット (`image_url_snapshot`) との突き合わせもURLで行うため、
**既に配布済みのカードの見た目を変えずに、後から取り込める**。付与時点では
取り込めていなくても、後で取り込めば次に開いたときからこちらの配信に切り替わる。

## 保存キーは内容から決まる

`collectibles/<sha256>.<ext>`。同じ画像が別のURLで届いても、ストレージ上は1つで済む。
内容が変わらないキーなので、配信時に長期キャッシュ (`immutable`) を許せる。

## 取り込みの安全性

こちらのサーバーが**外部の指定した宛先へ接続する**処理なので、SSRFの入口になりうる。

- **リダイレクト先も毎回検証する。** 最初のURLだけ検証して自動追従すると、検証を
  通したURLから内部ホストへ飛ばされてすり抜けられる (`redirect: "manual"` で追従を
  止め、追う前に検証する)。相対 `Location` も絶対URLへ直してから検証する
- 検証内容は `image-url-validator.ts` と共通 (HTTPS限定・SVG拒否・localhost/
  ループバック/プライベートIP/リンクローカルの拒否・URL長上限)
- **Content-Type ヘッダーを信用しない。** 送り手の申告であり実体の保証がないため、
  先頭バイト (マジックナンバー) から判定する。PNG / JPEG / GIF / WebP のみ受理し、
  SVG は中にスクリプトを書けるため実体側でも弾く
- 本文は読みながら上限 (`MAX_IMAGE_BYTES`) で打ち切る。`Content-Length` の申告を
  信じて確保しない (申告と実体が違う場合や、そもそも申告が無い場合に備える)
- リダイレクト回数とタイムアウトに上限を置く

## 配信

`GET /api/v1/collectible-images/<sha256>.<ext>`。

**認証を求めない。** カードの絵柄そのものは秘密ではなく、誰が持っているか
(`/me/collectibles`) の方が保護対象だから。URLは内容のハッシュなので、持っていない
カードのURLを推測して当てることはできない。

ウォレットと同一オリジンで返す相対パスにしているため、`next.config.mjs` の
`remotePatterns` に外部ホストを足す必要がない。

## 設定

管理画面「カード画像の保管先」(`/image-storage-config`) から設定する。

バケット・アクセスキーID・シークレットが**すべて揃ったときだけ有効**になる。揃わない
間は取り込みを行わず、これまでどおり外部URLをそのまま表示する。**未設定で起動を
止めない** — 画像の保管が使えないことより、ウォレット全体が起動しないことの方が
害が大きいため。

### 管理画面がある理由

鍵の入れ替えにデプロイを待たせないため (メール送信設定と同じ考え方)。環境変数でも
設定できるが、**管理画面の設定があればそちらが優先される**。

| 環境変数 | 用途 |
|---|---|
| `COLLECTIBLE_IMAGE_STORAGE_BUCKET` | バケット名 |
| `COLLECTIBLE_IMAGE_STORAGE_ACCESS_KEY_ID` | アクセスキー |
| `COLLECTIBLE_IMAGE_STORAGE_SECRET_ACCESS_KEY` | シークレット |
| `COLLECTIBLE_IMAGE_STORAGE_ENDPOINT` | Cloudflare R2 等で必要。S3なら未設定でよい |
| `COLLECTIBLE_IMAGE_STORAGE_REGION` | 未設定なら `auto` (R2はregionを見ない) |

環境変数は初期設定と緊急時の逃げ道として残している (管理画面へ入れるまでの間も
動かせるように)。

### シークレットの扱い

`ENCRYPTION_KEY` によるAES-256-GCM可逆暗号化で保存する (`MailConfig.apiKeyEncrypted`
と同方式)。**生値は画面にもAPIのレスポンスにも監査ログにも出さない** — 末尾4文字だけの
マスク表示になる。

空欄で保存しても現在の値は消えない。バケット等を直すたびに鍵を入れ直さずに済ませる
ため (共通顧客HUB設定・メール送信設定と同じ挙動)。

### 接続テスト

管理画面から、保存済みの設定で**実際に書いて読み戻す**。一覧の取得や存在確認では
**書き込み権限があるかが分からない**が、実際に必要なのは書き込みだから。書き先は
固定キー (`_wallet-connection-test`) で毎回上書きするため、ゴミが増えない。

誰がいつ試したかは監査ログに残す (本番と同じ鍵で外部へ書き込むため)。

## 取り込み状況を管理画面から見る

管理画面の「カード画像の取り込み状況」(`/collectible-image-ingest`)。
保管先の設定 (`/image-storage-config`) とは別の画面にしている。設定は滅多に触らない
シークレットの管理で、こちらは日々の取り込みが進んでいるかを見るためのもの。

内訳として、取り込み済み・取り込み待ち・失敗 (再試行する)・打ち切り・
**取り込み対象外** (カードに載っているのに対象へ入っていないURL) の件数を出す。
直近の失敗は取得元URL・試行回数・最終試行・理由を並べる。**失敗の理由は運用者向けで、
利用者の画面には出さない。**

「今すぐ取り込む」で定期実行 (15分ごと) を待たずに1回分走らせられる。外部への通信を
伴うため、枚数と時間の両方に上限を置いている。時間切れで取得しきれなかった分は次の
定期実行が拾うので、押し直す必要はない。

「打ち切った分も対象に戻す」にチェックを入れると `resetExhausted()` が走る。既定では
行わない — 壊れたURLを毎回叩き直さないためで、取得元の不具合が直ったときに使う。
戻しても `lastError` は消さない。取得元が直ったのかどうかを、戻したあとも運用者が
読めるようにするため。

保管先が未設定のときは何も動かさず、実行しなかったことを返す (押しても無反応に
見えるのを避けるため)。

| 操作 | SUPER_ADMIN / INTEGRATION_ADMIN | AUDITOR |
|---|---|---|
| 閲覧 | ✅ | ✅ |
| 手動実行 | ✅ | ❌ |

手動実行には**実行理由が必須**で、監査ログ (`COLLECTIBLE_IMAGE_INGEST_RUN`) に残る。

## 動作確認

- `image-bytes.test.ts` (10件) — 形式の判定、SVG・HTML・テキストの拒否、上限
- `image-fetcher.test.ts` (14件) — **リダイレクト先が内部ホストなら追わない**、
  相対Locationの絶対化、Content-Type の申告を信用しないこと、サイズ上限
- `collectible-images.service.test.ts` (22件) — 取り込み・重複排除・失敗の記録・
  配信URLの解決・再取得・**失敗しても例外を外へ出さないこと**・
  **保管先の設定より前に登録されたカードを拾い直すこと** (保有のスナップショット列を
  含む)・打ち切った分の戻し・手動実行の時間切れ
- `storage-config.service.test.ts` (13件) — 管理画面の設定が環境変数より優先されること、
  **シークレットが暗号化されて保存され生値が出ないこと**、空欄保存で消えないこと
- `e2e/admin-image-storage-config.test.ts` (9件) — 保存・マスク表示・権限
  (AUDITORは閲覧のみ)・**監査ログに鍵の生値が残らないこと**・接続テスト
- `e2e/admin-collectible-images.test.ts` (9件) — **取り込み対象外として見えること**・
  手動実行と監査ログ・失敗理由の表示・打ち切った分の戻し・保管先未設定時に
  何もしないこと・権限 (AUDITORは閲覧のみ)・未ログイン拒否

## まだやっていないこと

- **管理画面からの画像アップロード。** 現在はURLを入力する形のままで、入力された
  URLを取り込む。手元の画像を直接上げる導線は別途
- **使われなくなった画像の削除。** カードマスターの画像を差し替えても、古い実体は
  ストレージに残る
