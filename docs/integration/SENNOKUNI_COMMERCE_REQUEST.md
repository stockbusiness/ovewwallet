# 千ノ国マーケット様へのご依頼・ご確認（会員券のウォレット連携）

千ノ国ウォレット側で、**会員券を受け取る実装が完了しました**（2026-09-06）。接続に
進むにあたって、お渡しするものとご確認いただきたいことをまとめました。

> **2026-09-06 更新**: 先方からのご回答を受けて 0章を改めました。`source_system_key` は
> **貴社の既存値 `sengoku-market` をそのまま**お使いいただけます。変更は不要です。

NFTアートマーケットとは**別のマーケット**として扱います。両者が同じIDを採番されても
取り違えない作りになっています。

## 0. ウォレット側の受け口（確定値）

| 項目 | 値 |
|---|---|
| 受信エンドポイント | `https://api.sennokuni-wallet.com/api/integrations/events` |
| `source_system_key` | **`sengoku-market`**（貴社の既存値のままで結構です。`sengoku-commerce` も受け付けます） |
| 受け取るイベント | `entitlement.granted` / `entitlement.revoked` |
| `event_version` | `1.0` または `1.1` |
| 認証ヘッダー | `X-SenNoKuni-Key-Id` / `X-SenNoKuni-Timestamp` / `X-SenNoKuni-Nonce` / `X-SenNoKuni-Signature` |
| 署名対象（LF区切り） | `key_id \n timestamp \n nonce \n METHOD \n path(クエリ除く) \n リクエストボディ生文字列` |
| 署名アルゴリズム | HMAC-SHA256 |
| 時刻のずれ | **±5分**まで。超えると401 |
| nonce | 同じ値の再利用は5分間拒否 |
| `Idempotency-Key` ヘッダー | **必須**。本文の `event_id` と一致させてください |
| 署名鍵 | 別途お渡しします（本書には記載しません） |

## 1. 会員券の送信例

```json
{
  "event_id": "evt_01J8XYZ...",
  "event_type": "entitlement.granted",
  "event_version": "1.1",
  "occurred_at": "2026-09-10T03:12:00.000Z",
  "source_system_key": "sengoku-commerce",
  "target_site_key": "ovew-wallet",
  "common_user_id": "cu_0123456789abcdef0123456789abcdef",
  "valid_from": "2026-10-01T00:00:00.000Z",
  "valid_to":   "2027-09-30T14:59:59.000Z",
  "data": {
    "entitlement_id": "mem_000123",
    "order_id": "ord_000987",
    "order_item_id": "itm_000987_1",
    "product_code": "MEMBER-GOLD"
  },
  "metadata": {
    "entitlement_type": "MEMBERSHIP_PASS",
    "asset_code": "MEMBER-GOLD-2026",
    "name": "千ノ国 ゴールド会員券",
    "description": "2026年度のゴールド会員券です",
    "image_url": "https://cdn.example.com/passes/gold.png",
    "thumbnail_url": "https://cdn.example.com/passes/gold_thumb.png",
    "serial_number": "0034"
  }
}
```

**必須項目**: `event_id` / `event_type` / `event_version` / `occurred_at` /
`source_system_key` / `common_user_id` / `data.entitlement_id` /
`metadata.entitlement_type` / `metadata.asset_code` / `metadata.name` /
`metadata.image_url`

**`metadata.entitlement_type` は `MEMBERSHIP_PASS`** としてください
（`membership_pass` も受け付けます）。**この値でないと受け取れません。**
アートマーケット用の `DIGITAL_COLLECTIBLE` を送られた場合は400で返します
（設定の取り違えに双方が気づけるようにするためです）。

`quantity` を送られる場合は **1のみ**です。複数枚をまとめた付与には対応していません
（1件ずつ送ってください）。

## 2. 有効期限について

**期限のあるものと無いものがある**と伺いましたので、両方に対応しています。

- **期限あり**: `valid_to` を **ISO 8601** で送ってください（`valid_from` も任意で
  受け取ります）。上の例のように**本文の直下**に置いてください（`data` の中では
  ありません）
- **期限なし**: `valid_to` を**送らない**でください（未送信・`null` は「期限なし」
  として扱います）

**期限切れはウォレット側が日付から自動で判定します。** 期限が来たときに
`entitlement.revoked` を送っていただく必要はありません。利用者の画面には「期限切れ」と
表示され、保有していた記録は残ります（消しません）。

⚠️ **日付として読めない値は400で拒否します。** `"2026年3月31日"` のような形式は
受け付けません。黙って無視すると「期限なし」になってしまい、期限切れの会員券が
有効に見えてしまうためです。

**ご確認**: 期限切れのときに、そちらから `entitlement.revoked` を送るご予定は
ありますか。送っていただいても問題ありません（取消として記録します）が、
**送らなくても期限切れの表示は正しく出ます**。どちらの運用にされるかお知らせください。

## 3. ご確認いただきたいこと

### 3-1. 受取人の特定方法 ← **最も重要**

`common_user_id` が**必須**です。この値で受取人を決めます。

**その `common_user_id` にウォレットのアカウントが紐付いていないと、付与は
受け付けられません**（エラーを返し、再送対象になります）。

1. 購入者の `common_user_id` をどのように取得されますか（共通顧客HUB経由／その他）
2. **ウォレット未登録の方が会員券を購入された場合**、どうなさいますか。ウォレット
   登録前にイベントを送ると失敗します
3. `source_user_id` も併せて送っていただけますか（調査時の突き合わせに使います）

### 3-2. `entitlement_id` の採番

`entitlement_id` は**取消の冪等キー**として使います。

- 1つの会員券に対して**不変**でしょうか（再送しても同じ値か）
- 千ノ国マーケット内で**一意**でしょうか
- 桁数・形式をお知らせください

なお **NFTアートマーケットと同じ値になっても構いません。** マーケットごとに別々に
管理しているため、取り違えは起きません。

### 3-3. 会員券の画像

ウォレット側で画像を取り込んで自前で配信します（そちらの配信が止まっても会員券が
見えなくならないようにするためです）。次の条件をお願いします。

- **https のみ**（http は受け付けません）
- **PNG / JPEG / GIF / WebP**。**SVGは不可**（中にスクリプトを書けてしまうため）
- **8MB 以下**
- 取り込みのために**認証なしで取得できる**こと
- リダイレクトは3回まで追います。内部ホスト・プライベートIPへのリダイレクトは
  拒否します

### 3-4. 取消（`entitlement.revoked`）

- どのような場合に送信されますか（返金・キャンセル・会員資格の停止など）
- `reason_code` は何を送られますか。ウォレット側は現在 `full_refund` のみ表示文言を
  持っており、それ以外は受理はしますが記録のみです。**使用予定の値の一覧**を
  お知らせください
- **付与したのと同じ `source_system_key`（`sengoku-market`）からのみ**取消を
  受け付けます

### 3-5. 会員券の種類

複数の種類（ゴールド・シルバー等）を扱われますか。ある場合は `metadata.asset_code` を
種類ごとに分けてください。ウォレット側はこの値で券の種類をまとめます。

### 3-6. 試験環境

本番の前に検証環境で疎通を確認したいと考えています。

- そちらに検証環境はありますか
- 検証用の署名鍵を別途発行しましょうか
- 疎通確認の希望時期

## 5. お渡しするもの

**署名鍵（key_id と secret）** を発行してお渡しします。この鍵は `sengoku-market` に
