# お知らせの既読管理・重要度フラグ

2026-07-19実装。お知らせに重要度 (`NORMAL`/`IMPORTANT`) を設定できるようにし、
ユーザーごとの既読状態を追跡できるようにした。

## 仕組み

- `Notice.importance` (`NoticeImportance`enum、既定`NORMAL`): 管理画面のお知らせ作成
  フォームで「通常」「重要」を選択する。`IMPORTANT`のお知らせはユーザー画面 (ウォレット
  ホームのInfoCard・お知らせ一覧) で深紅の枠線と「【重要】」ラベルで強調表示される。
  LINE配信 (`docs/notices-line-broadcast.md`) のテキストにも反映される。
- `NoticeRead` テーブル (`notice_id` + `ove_account_id` に unique制約): 行が存在すれば
  既読、存在しなければ未読というシンプルなモデル。お知らせ自体は全ユーザー共通で
  1行のみ存在し、既読状態だけをアカウント単位で別テーブルに持つ。
- `GET /api/v1/me/notices`: 各お知らせに呼び出し元アカウントの既読状態を突き合わせて
  `is_read`を付与して返す。
- `POST /api/v1/me/notices/:noticeId/read`: 既読にする (upsertのため複数回呼んでも
  冪等)。お知らせ一覧画面 (`/wallet/notices`) を開いた時点で、表示されている未読分を
  まとめて既読にする (メール受信箱等でよくある「開いたら既読」という挙動)。

## UI

- ウォレットホームのベルアイコンは `/wallet/notices` へのリンクとし、未読のお知らせが
  1件でもあれば赤いドットを表示する (以前は常時表示の装飾のみだった)。
- `InfoCard`共通コンポーネントに`important`/`unread`propsを追加し、ウォレットホームの
  最新のお知らせ表示にも重要度・未読状態を反映する。

## 動作確認

`apps/api/src/e2e/notices.test.ts` (2件): 重要度を指定した作成とユーザー向け一覧への
反映、既読化がアカウント単位で独立していること (他アカウントの既読状態に影響しない)・
二重に既読にしてもエラーにならないことを検証済み。

2026-07-19、Playwrightによる実ブラウザ確認を実施し、未読お知らせがある状態で
ウォレットホームのベルアイコンに赤いドットが表示されること、`IMPORTANT`指定の
お知らせが深紅の枠線と「【重要】」ラベルで強調表示されること、`/wallet/notices`
画面を開くと未読分が既読化され赤いドットが消えることを確認した。
