# 獲得機会への誘導 (案内先URL)

2026-08-31実装。付与ルールごとに「参加方法の案内先」(LINE友だち追加など) を設定し、
ウォレットから誘導できるようにした。

## 導入前の状態

ウォレットの「ORIを貯める」(`/wallet/earn`) には、既に **「AIアート教室参加特典
+10,000 ORI」** が並んでいた。しかしタップすると

```
「AIアート教室への案内は準備中です」
```

というトーストが出るだけで、**行き止まり**だった。「ORIを貯めたい」と思って一覧を開き、
金額に反応して指を動かした、いちばん濃い見込み客がそこで止まっていた。

## URLをコードに埋めない理由

`RewardRule.landing_url` としてDBに持ち、管理画面から編集する。

- LINEの友だち追加URLは変わる (アカウント作り直し、計測パラメータの付け替え)。
  コードに埋めると**変更のたびにデプロイが必要**になる
- 運用側が自分で変えられる
- **戦国ガチャ・EC等も同じ行き止まり**なので、仕組みを1つ足せば全サービスに効く。
  AIアート教室専用の作り込みにしない

## URLの検証 (httpsのみ)

管理画面から入力された値が、そのまま利用者の画面のリンクになる。`javascript:` や
`data:` を許すと、リンクを踏んだ利用者のブラウザで任意のスクリプトが動きうる
(管理者アカウントが乗っ取られた場合の被害を、利用者側まで広げないための多層防御)。

`apps/api/src/rewards/landing-url.ts` で **https のみ**を許可し、それ以外は400で拒否する。
httpを許さないのは、現実の案内先がすべてhttpsであり平文を許す理由が無いため。

空文字を送ると未設定に戻せる (導線を出さない状態にする)。

外部リンクには `rel="noopener noreferrer"` を付け、遷移先から `window.opener` 経由で
ウォレットの画面を操作されないようにしている。

## 出し分け (`already_earned`)

参加特典は `perEventLimit: 1` のように**1回限り**のものがある。受け取り済みの人に
「10,000 ORI もらえます」と出し続けるのは事実に反する。

`GET /api/v1/rewards/public` が利用者ごとに `already_earned` を返す。判定は
`RULE_CODE_BY_TRANSACTION_TYPE` (rule_code ⇔ transaction_type の対応表) を使い、
その種別のCREDIT取引があるかを見る。

取消済み (`REVERSED`) は含めない。取り消された付与は受け取っていないのと同じで、
上限判定でも消費扱いにならないため、案内は再び出すのが正しい。

### 既知の制約

**対応表に載っていないルールは、常に `already_earned: false` になる。** 現在対応表に
あるのは登録特典・AIアート教室・EC購入・学習ミッションの4つ。

誤って「受け取り済み」と判定して獲得機会を隠すより、出し続ける方が害が小さいため、
この方向に倒している。新しい1回限りの特典を作る場合は、対応表にも追加すること。

## 表示場所

| 場所 | 出すもの |
|---|---|
| `/wallet/earn` (一覧) | 案内先があれば実リンク、無ければ従来の「準備中です」 |
| `/wallet` (ホーム) | 案内先があり未受け取りのうち、**獲得額が最大の1件だけ** |

ホームで1件に絞るのは、**残高確認の画面であって獲得機会を並べる場所ではない**ため
(一覧は「ORIを貯める」にある)。

モーダルやポップアップでの割り込みは採用していない。残高を見に来た利用者の邪魔になり、
離脱を招くため。

## 計測

リンクには設置場所ごとのパラメータを付ける。どちらが効いたか分かるようにするため。

| 場所 | パラメータ |
|---|---|
| ホーム | `?utm_source=ori_wallet&utm_medium=dashboard` |
| 「ORIを貯める」一覧 | `?utm_source=ori_wallet&utm_medium=earn_list` |

案内先URLに既にクエリがある場合は `&` で連結する。

## 設定手順

1. 管理画面「付与ルール管理」を開く
2. 対象ルールの「案内先URL」列で「設定」を押す
3. `https://` で始まるURLを入力する (空にすると導線を出さなくなる)

デプロイは不要。設定した時点で利用者の画面に反映される。

## 動作確認

- `apps/api/src/rewards/landing-url.test.ts` (4件): httpsの通過、空文字のnull化、
  https以外の拒否、URLとして不正な値の拒否
- `apps/api/src/e2e/reward-landing-url.test.ts` (8件): 管理画面からの設定と利用者向け
  APIへの反映、未設定への差し戻し、https以外の400拒否、**拒否時に値が書き換わらない
  こと**、受け取り済み判定 (未受け取り/受け取り済み/他人に影響されない/対応表に無い
  ルールは常にfalse)
