# 利用者からの問い合わせ

2026-09-06実装。利用者が困ったときに取れる行動が無かったため用意した。

退会はできるようになったが、「付与されない」「残高が合わない」ときに、利用者からは
どこにも言う先が無い状態だった (画面のどこにも問い合わせ先が無く、`/company` の
会社情報もプレースホルダーのまま)。

## メールアドレスの案内にしなかった理由

**問い合わせの内容だけでは、誰のことか分からないため。**

「ORIが入っていません」と書かれても、どのアカウントのどの時点の話かが分からなければ
調べようがない。メールで受けると、その紐付けを利用者の自己申告 (アカウント番号を
正確に書き写してもらう) に頼ることになる。

本人のセッションから受ければ、**アカウントは確実に決まる**。利用者はアカウント番号を
書く必要がなく、運用側は受け取った時点で取引履歴・残高をそのまま調べられる。

## 返信の仕組みを新しく作っていない

返信は**本人宛の個別お知らせ** (`notices` の `ove_account_id` が本人のもの) として
作る。この仕組みは失効予告で既に使っており、利用者向けの一覧
(`WalletsService.listPublicNotices`) も既に本人宛を拾うようになっている。

利用者から見ると、返信は普段のお知らせと同じ場所に届く。返信を読むために新しい画面を
覚える必要がない。

**退会済みの相手には返信できない** (400)。お知らせを作っても本人はもうログインできず、
「送った」という記録だけが残って対応済みに見えてしまうため。

## 画面

### 利用者 (`/wallet/support`)

メニューの「お問い合わせ」から。種類 (付与されない / 残高が合わない / ログイン・
アカウント / カード / その他) と本文を送る。送信すると受付番号 (`OVE-INQ-000001`) を
返す。

**自分が送ったものの一覧を同じ画面に出す。** 送りっぱなしにすると、届いているのか
見てもらえているのかが分からず、同じ内容を何度も送ることになる。状態は運用側の語
そのままではなく、利用者向けの言い方にする (`OPEN` → 「受付済み」など)。

### 管理者 (`/support-inquiries`)

状態で絞り込める一覧。未対応を先に出す (作成順だけだと、古い対応済みが上に居座る)。
アカウント番号はアカウント一覧へのリンクにしてある。

**運用メモは利用者に見えない。** 調査の経過を残す欄で、返信本文とは別に保存する。

| 操作 | SUPER_ADMIN / OVE_OPERATOR | AUDITOR |
|---|---|---|
| 閲覧 | ✅ | ✅ |
| 状態変更・メモ | ✅ | ❌ |
| 返信 | ✅ | ❌ |

問い合わせ本文には利用者の個人的な事情が書かれうるため、閲覧できるロールをお知らせの
管理と同じ範囲に絞っている。

## 歯止め

- **送信回数**: 1時間に5件 (`@Throttle`)。困っている人を止めない範囲で、いたずらに
  何百件も入らない程度。
- **同じ本文の連投**: 直前5分以内に同じ本文があれば400。連打で同じ内容が並ぶと、
  運用側がどれを見ればよいか分からなくなる。利用者への文言は「すでに受け付けています」
  とし、届いていることが伝わるようにする。
- **本文の長さ**: 2000文字。長い経緯を書ける余裕は要るが、画面にそのまま出す値なので
  運用側が読める範囲に収める。

## 監査ログ

- `SUPPORT_INQUIRY_STATUS_CHANGED` — 状態の変更 (前後の状態を記録)
- `SUPPORT_INQUIRY_ANSWERED` — 返信 (作ったお知らせのIDと件名を記録)

## 動作確認

`apps/api/src/e2e/support-inquiries.test.ts` (10件): **アカウントが自己申告ではなく
セッションから決まること**、他人の問い合わせが見えないこと、同じ本文の二重登録、
空本文の拒否、未ログイン拒否、**返信が本人にだけ届き他人には届かないこと**、
**運用メモが利用者向けの経路に出ないこと**、退会済みへの返信拒否、権限
(AUDITORは閲覧のみ)、未ログインの管理API。

### 意図的に壊して確認

| 壊した箇所 | 落ちたテスト |
|---|---|
| 利用者向けの形に運用メモを混ぜる | 「運用メモは利用者向けの経路に出ない」 |
| 本人以外の問い合わせも返す | 「自分の問い合わせだけが見え、他人のものは見えない」 |
| 返信を全員向けお知らせにする | 「返信すると本人だけに見えるお知らせが届き、他人には届かない」 |
| 退会済みにも返信させる | 上記2件 |

## まだやっていないこと

- **ログインできない人の問い合わせ先。** この画面はログインが前提なので、ログイン
  自体ができない利用者は使えない。`/company` の会社情報に連絡先を記載する必要がある
  (現在プレースホルダーのまま、`docs/legal-documents.md`)。
- **未対応件数の通知。** 管理画面を開かないと溜まっていることに気づけない。
- **利用者への返信の個別プッシュ。** お知らせは本人宛に作られるが、届いたことを
  能動的に知らせる手段は無い (LINE配信は友だち全員向けのみ、
  `docs/notices-line-broadcast.md`)。
- **添付ファイル。** 画面の写真を送れると調査は速くなるが、保管と削除の設計が要る。
